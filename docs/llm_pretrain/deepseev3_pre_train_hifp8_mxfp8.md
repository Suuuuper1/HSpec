# HiF8精度&性能双突破——基于昇腾950DT的大模型训练低精度优化实践
# 第一章 HiF8 数据格式介绍

本章首先介绍华为全新自研的 8-bit 浮点数据格式 HiF8（HiFloat8），重点说明其编码模式及对特殊值的支持特性。相较于传统的 FP8（E4M3/E5M2）格式，HiF8 通过优化的阶码与尾数的分配，显著提升了动态范围与表示精度。在此基础上，HiF8 提出了一种创新的通用浮点编解码方法，使其字段宽度、动态范围及精度均可根据具体场景的需求进行缩放。值得注意的是，HiF8 额外引入了 **Dot ​**字段。如表 1 所示，该格式由**​符号（Sign）、​**​​**点位（Dot）**​、**​阶码（Exponent）​**和**​尾数（Mantissa）​**四个核心字段组成。

**表 1：HiF8 的字段结构**

| 字段 | 宽度（bit） | 说明 |
| - | - | - |
| 符号（S） | 1 | 数值符号，1表示负，0表示正 |
| 点位（D）                                  | 2\~4 | 指示指数域宽度及**Denormal 编码模式（DML）** |
| 阶码（E）                                  | D 位 | 采用符号-幅度编码（Sign-Magnitude） |
| 尾数（M）                                  | 1\~3 | 省略前导1的尾数位

以下是每个字段的详细说明：

* ​符号域 (Sign Field)：1 位，用于决定 HiF8 数值的正负符号。默认情况下，1 表示负号，0 表示正号。
* ​点位域 (Dot Field)​：采用前缀编码，不同编码长度对应不同的 Dot 值，如表 2 所示。

**表 2：Dot 编码**

| 位宽 | 编码 | 编码值 |
| - | - | - |
| 2 | 11 | 4 |
| 2 | 10 | 3 |
| 2 | 01 | 2 |
| 3 | 001 | 1 |
| 4 | 0001 | 0 |
| 4 | 0000 | **DML** |

* ​阶码域 (Exponent Field)​：D 位（包含一个未存储的、值为 1 的隐含前导数值位），其中 D 等于 Dot 字段的编码值，且 D∈{0, 1, 2, 3, 4}。
* ​尾数域 (Mantissa Field)​：1 到 3 位，使用无符号整数编码。对于 HiF8 的规格化数，尾数表示有效数字中的小数部分，即二进制小数点右侧的部分。

## 1.1 Normal 编码模式

![](./figures/deepseek_v3/image1.png)
**图 1：HiF8 的 Normal 编码模式结构及其阶码幅值分配示意图**

图 1 展示了 HiF8 的 Normal（规格化）编码模式。为确保不同位宽阶码域对应的指数范围互不重叠，并实现​**无冗余编码**​，HiF8 采用 **Sign-Magnitude ​**编码方案，并将幅值的最高位设为隐含位，不占用实际存储空间。

具体而言：

* 当 Dot = 0 时，说明阶码不占据位宽，且 E 直接等于 0；
* 而当 Dot = 1\~4 时，固定阶码幅值的最高位为 1（图 1 中的红色数字）。

在这种规则下：

* Dot = 1，阶码 E 只能等于 ±1，不包含已经编码的 0；
* Dot = 2 时，阶码 E 只能表示 ±[2, 3]，不包含已经编码的 [-1, 1]。以此类推，Dot 域指示的 0\~4 共五种位宽阶码，共编码了 [-15,  15] 的指数，且彼此之间不重复，实现了无冗余编码。

此外，HiF8 采用大位宽的 Dot 域匹配小位宽(小幅值)阶码域的设计，从而实现了尾数精度的平滑渐变而非断层式跳变。观察可见，在 E = [-3,  3] 时，有 3-bit 尾数。然后随着阶码幅值变大，Normal 模式下的尾数位宽才逐渐收缩至 1-bit。这种精度渐变的特性，正是 HiF8 优于其借鉴对象 Posit 数据格式的关键所在。

## 1.2 Denormal 编码模式

![](./figures/deepseek_v3/image2.png)
**图 2：**HiF8 的 Denormal 编码模式结构及其阶码幅值分配示意图****

为了支持更大的动态范围，HiF8 还采用了不同于 IEEE 754 风格的 Subnormal / Denormal 方案。如图 2 所示，在**​ ​**Denormal（非规格化）模式下：

* ​**编码逻辑转换**​：当 Dot 域指示当前数值处于 Denormal 模式时，HiF8 将不再保留独立的阶码域。此时，原有的 3-bit 尾数空间（可编码 0\~7 共 8 个离散值）将被​**直接复用，以映射并扩展极小值的指数表示范围**​。
* ​**指数范围扩展**​：在 **Normal** 模式支持的 [-15,  15] (共 31 个指数)的基础上，Denormal 模式额外开辟了 [-22,  -16] 共 7 个指数。其中，编码 0 对应  -23，用于表示特殊值 **Zero ​**和 **NaN。**
* ​**性能对标**​：由此，HiF8 实现了覆盖 [-22,  15] 共 38 个指数的大动态范围，已经非常接近 FP16 的 [-24,  15] 的指数覆盖范围。同时，由于 [-15,  -8] 区间本身是 1-bit 尾数，新增扩展的 [-22,  -16] 区间对应 0-bit 尾数，二者在表示精度上保持连续过渡，而非突变。

## 1.3 特殊值

**表 3：HiF8 的特殊值定义**

| 条件 | 输出 X | HiF8 (二进制) | HiF8 (十六进制) | 含义 |
| - | - | - | - | - |
| S=0, D=DML, M=3'b0 | **Zero** | `00000000` | `0x00` | 零 |
| S=1, D=DML, M=3'b0                                                   | **NaN** | `10000000` | `0x80` | 非数字 |
| D=4, Es=4'b0111,  M=1                                                | **±Inf** | `X1101111` | `0x6F`/`0xEF` | 正负无穷大 |

如表 3 所示，除了常规数值编码，HiF8 还完整支持 Zero、NaN 和 ±Inf 等核心特殊值。HiF8 不区分正 0 和负 0，而是采用单一编码模式的统一表示。这种设计有效节省了编码空间，使 HiF8 成为一种数值表达完备且高效的 8-bit 单格式。

## 1.4 HiF8 的核心特性

HiF8 具备一系列专为大模型（LLM）训练量身定制的优良特性，核心优势主要体现在以下三个方面：

* ​**契合数据分布的锥形精度（Tapered Precision）**​：传统的 FP8（E4M3/E5M2）因阶码位宽固定，往往难以同时兼顾深度学习所需的动态范围与有效精度。考虑到神经网络的参数与激活值通常呈现类高斯分布，HiF8 创新性地采用了​**锥形精度分布**​（如图 3 所示），将更高的精度集中在高频出现的数值区间，从而更好地匹配模型数据特征。

![](./figures/deepseek_v3/image3.png)

**图 3：8-bit 浮点数格式有效位-指数示意图**

* ​**无冗余编码**​：HiF8 的阶码采用原码编码，并将固定的 1-bit 高位设为隐含位，不占用实际存储空间，从而确保不同位宽阶码的表达范围互不重叠，最终实现无冗余编码。
* ​**大动态范围**​：通过特殊的 **Denormal** 设计，将综合指数范围从 [-15,  15] 扩展至 [-22,  15]，共覆盖 38 个指数值，已经接近 FP16 的 40 个综合指数值表达范围。表 4 对 HiF8、FP8 与 FP16 的典型值及关键特征进行了总结和对比。可以看到，HiF8 在 8-bit 位宽限制下，通过匹配数据分布的锥形精度特性，在保证神经网络训练与推理所需精度的前提下，显著扩大了格式的动态范围，为神经网络提供了能力更全面的 8-bit 单格式表示。

# 第二章 量化方案

在执行量化时，高精度数据（如 FP32/BF16）向低比特（如 FP8）转换的核心在于​**缩放处理（Scaling）**​。针对给定数据块 X，需通过乘以一个​**缩放因子（Scaling Factor, Scale）**​，使 X 中的原始数值能够安全、无溢出地映射至低比特的动态范围内。公式（1）和公式（2）描述了量化过程中的基本缩放原理。其中，F8max 表示目标 8 比特浮点格式可表示的最大值（例如 FP8-E4M3 的最大值为 448），Amax 表示数据块 X 中元素的最大绝对值。公式（1）用于计算​**缩放因子 Scale**​，公式（2）用于将高精度数据映射至低比特表示范围。

$$
\mathrm{Scale} = \frac{A_{\max}}{F8_{\max}} \tag{1}
$$

$$
X_{\mathrm{scaled}} = X \cdot \mathrm{Scale} = X \cdot \frac{A_{\max}}{F8_{\max}} \tag{2}
$$

尽管 8-bit 浮点数（FP8）在动态范围上相较于定点数具有天然优势，但在仅有的 8 位位宽限制下，其精度表达能力与数值覆盖范围仍然有限。为了最大限度地抑制从高精度（如 FP16 / BF16）向 FP8 转换时的量化损失，业界通常引入“细粒度量化（Fine-Grained Quantization）”策略**。** 如图 4 所示，该策略通过大幅增加缩放因子（Scaling Factor）的密度来实时调整数据映射范围，主要体现在以下两个维度：

* 激活值的 Per-Token 细粒度（针对动态分布）：由于 LLM 中的激活值（Activation）通常在不同的 Token 维度上具有较大的动态范围差异，并伴随频繁的离群值。Per-Token 缩放为每个输入 Token（或 Tile）应用一个独立的缩放因子，以确保每个 Token 的核心数据范围能被 FP8 格式有效覆盖，从而保持量化精度。
* 权重的 Per-channel / Per-Block 细粒度（针对静态分布）：模型权重（Weight）的分布在不同的输出通道（Channel）或权重块（Block）之间通常具有不同的分布特征。Per-Channel / Per-Block 缩放通过为每个通道或每个权重块应用独立的缩放因子，来进一步降低量化误差，提升模型推理精度。典型的 Block 大小可设为 `128 × 128`。

然而，这种对精度的极致追求，引入大量的 Per-Token / Channel / Block 缩放因子，会显著增加硬件实现和控制逻辑的复杂性。在推理过程中，系统需要频繁加载、存储并应用这些额外的缩放因子，从而带来额外的内存带宽开销和计算延迟，部分抵消 8-bit 浮点计算本身带来的加速收益。

![](./figures/deepseek_v3/image5.png)

**图 4：常见量化粒度示意图**

由于 HiF8 具备更大的​**动态范围**​，在训练中往往可以采用粗颗粒度的 Per-Tensor 量化，而 FP8、MXFP8 等格式往往需要 Per-Block 量化。

# 第三章 训练方案

## 3.1 常见训练方案

在介绍基于低比特（如 HiF8）的量化训练方案前，有必要先回顾目前业界最广泛使用的基线方案——基于 BF16 的混合精度训练。

* ​**BFloat16（BF16）格式**​：BF16 是 2017 年提出的一种专为 Deep Learning 设计的 16-bit 浮点数格式。在内存布局上，它由 1-bit 的 Sign、8-bit 的 Exponent 和 7-bit 的 Mantissa 组成。 与传统的 FP16（5-bit Exponent，10-bit Mantissa）相比，BF16 牺牲了 Mantissa 的精度，但保留了与高精度数据类型 FP32 完全相同的 Exponent 位宽。这意味着 BF16 拥有与 FP32 相同的动态范围（约 $10^{38}$ 到 $10^{-38}$ ）。在神经网络的训练中，模型参数和梯度的分布通常跨越极大的数值范围，使用 BF16 可以有效避免由于表达范围不足而导致的上溢或下溢，同时其较小的位宽又能显著降低显存占用与内存带宽开销。
* ​**基于 BF16 的混合精度训练**​：主流深度学习框架在支持 BF16 训练时通常采用自动混合精度（Automatic Mixed Precision, AMP）机制。 该范式在图层或算子层级选择合适的数据类型：在前向计算（Forward Pass）和反向传播（Backward Pass）中，框架会将计算密集型算子（如 MatMul、Convolution）的输入自动下采样转换为 BF16，以充分发挥底层硬件的加速优势；而对于对数值精度高度敏感的算子（如 Softmax、LayerNorm、Loss 计算等），则保持 FP32 以确保数值稳定性。此外，在 Optimizer 的参数更新步骤中，系统往往在内存中维护一份 FP32 高精度主权重（Master Weights），从而避免因 BF16 Mantissa 精度不足而导致的权重更新停滞。

在上述混合精度方案基础上，基于缩放（Scaling）技术的 8-bit 混合精度训练可以进一步提升训练效率。

## 3.2 缩放方案

当前主流的 8-bit 混合精度训练方案通常涉及两类缩放策略：Current Scaling 和 Delayed Scaling。如图 5 所示，Current Scaling 在每个训练步都遍历输入 ***X***​****​  ​****中的高精度数据，获得最大绝对值 Amax，并基于该 Amax 值完成缩放。这意味着求取 Amax 与计算 Scale 的过程在每次迭代中都需要执行，且与下游计算（如 MatMul）串行，从而部分抵消 8-bit 带来的性能收益。相较之下，图 6 展示的 Delayed Scaling 利用历史统计值对当前训练步的 Amax 作估计，将遍历输入*​ ​*​***X***​***​  ​***求取 Amax 的操作与后续运算解耦，因此能够更充分地发挥 8-bit 训练的性能优势。

![](./figures/deepseek_v3/image6.png)

**图 5：Current Scaling 以 iteration 为周期计算 Amax，将输入 X 缩放至 Float8 表达范围内**

![](./figures/deepseek_v3/image7.png)

**图 6：Delayed Scaling 以 interval = K iterations 为周期计算 Amax，将输入 X 缩放至 Float8 表达范围内，其中 N_guard 为防止上溢的保护参数**

常用于 8-bit 混合精度训练的 FP8-E4M3 因其动态范围较小，往往需要采用细颗粒度的 ​**Current Scaling**​，而 HiF8 得益于其在精度和动态范围间所取得的平衡，能够采用​**​ Delayed Scaling**​，并以较长的周期（interval）估计 **Amax** 值，同时仍保持训练稳定性。

# 第四章 低精度训练框架

## 4.1 MindSpeed 低精度训练框架

本文后续的 HiF8 与 MXFP8 混合精度验证基于 MindSpeed 和 MindSpeed LLM 训练框架开展。MindSpeed Core 是面向华为昇腾设备的大模型加速库，可帮助大模型训练与推理任务高效迁移至昇腾平台，并支持昇腾专有优化能力。在 MindSpeed Core 的基础上，系统进一步提供了面向大语言模型场景的 MindSpeed LLM 组件，其整体框架如图 7 所示。

![](./figures/deepseek_v3/image8.png)

**图 7：MindSpeed 与 MindSpeed LLM 框架示意图**

Transformer Engine（TE）是一个面向 Transformer 模型训练与推理的加速库，支持在 Hopper GPU 上使用 8-bit 浮点（FP8）精度，以降低内存占用并提升训练和推理性能。MindSpeed 的 TE 模块与官方 TE 在接口和能力上保持兼容，支持第三方框架无缝迁移，可在昇腾 NPU 上实现高效的大语言模型训练与推理。
MindSpeed 低精度训练流程的核心在于，将前向传播（Fprop）、激活反向传播（Dgrad）和权重反向传播（Wgrad）过程中的通用矩阵乘法运算量化为 FP8 / HiF8 精度执行。 整体训练流程仍基于 BF16 / FP16 的 AMP 混合精度模式，但在特定计算算子中，尤其是 Linear 层中的矩阵乘法运算（涵盖 Fprop、Dgrad 和 Wgrad），采用 FP8 / HiF8 精度路径执行。
![](./figures/deepseek_v3/image9.png)

**图 8：Transformer Engine 量化代码模块实现**

如图 8 所示，TERowParallelLinear 和 TEColumnParallelLinear 对应 Linear 层实现，其核心是将 Fprop、Dgrad 和 Wgrad 中的 MatMul 运算替换为 FP8 / HiF8 低精度路径。FP8GlobalStateManager 是一个单例对象，用于维护全局 FP8 状态以及各 TE Module 的运行信息。各 Recipe 类负责执行不同的量化策略，并通过对应的 Tensor 类管理 Scale 与数据张量。

在高精度张量量化为低精度张量的过程中，FP8 数据格式通常支持以下几类缩放策略：

* Delayed Scaling：根据历史 Amax 值计算缩放因子（Scaling Factor），再使用该缩放因子对 Tensor 进行量化；
* Tensorwise Scaling：在线计算 Amax，并实时应用缩放因子对 Tensor 进行量化；
* Blockwise Scaling：对 Tensor 进行分块，然后分别计算 Amax 并应用 Scaling factor 对 Tensor 进行量化；
* MX Scaling： 通过块级共享 Scale 与低位宽元素组合，将浮点向量转化为 MX 块，实现动态量化。

* ​**初始化阶段（init）**​：主要校验当前环境，例如是否已安装 TorchAO、当前硬件环境是否支持 MXFP8，并完成相关 Python 包导入及配置初始化。初始化完成后，将 enable 标志位置为 1。
* ​**转换阶段（convert）**​：在确认 enable 标志有效后，系统导入 TorchAO 相关 Python 包，读取 config 配置，并调用 `quantize_` 完成模型转换。其中，`quantize_` 的核心参数包括待转换模型 `model`、量化配置 `config` 以及用于筛选待转换层的 `filter_fn`。

## 6.1 HiF8 相对 BF16 的收益来源

相较于 BF16，HiF8 的性能增益主要来自数据位宽降低后带来的访存收益，以及低比特计算路径的吞吐优势。

### 6.1.1 数据位宽减半带来的访存收益

当数据位宽从 BF16 的 16-bit 降至 HiF8 的 8-bit 后，矩阵乘相关算子的输入、输出及中间激活值的数据搬运量同步下降。在大模型训练中，部分算子往往受存储带宽限制，因此位宽减半通常可以带来以下几方面收益：

* ​**降低片上内存带宽压力**​：单位时间内传输的数据量减少，从而缓解高带宽片上内存的读写压力；
* ​**提高片上缓存利用率**​：在相同片上 SRAM / Cache 容量下，可容纳更多数据，有助于提高数据复用率；
* ​**减少数据搬运延迟**​：从片上内存到寄存器等不同存储层级之间的数据传输开销下降，从而缩短非计算阶段的等待时间。

### 6.1.2 8-bit 计算吞吐提升效应

除访存收益外，HiF8 还能够利用底层硬件面向低比特矩阵运算提供的更高吞吐能力。当前 AI 加速硬件通常针对 8-bit 计算路径做了专门优化，因此当 MM 和 GMM 等主干算子映射到 HiF8 路径后，能够进一步提高算力利用率，并转化为训练速度提升。如图 13 所示，HiF8 相对 BF16 的 MM 与 GMM 算子平均加速比超过 1.8 倍。

## 6.2 HiF8 相对 MXFP8 的收益来源

与 MXFP8 相比，HiF8 的额外收益主要与量化粒度及缩放元数据开销有关。在 DeepSeek-v3 裁剪网络中，GMM 算子在 HiF8 与 MXFP8 两种量化方案下的 profiling 对比如图 14 所示。结合实验结果，可以将 HiF8 相对 MXFP8 的优势概括为以下三个方面。

![](./figures/deepseek_v3/image15.png)

**图 14：HiF8 vs. MXFP8 GMM 量化算子 profiling 对比示意图**

### 6.2.1 缩放元数据开销较低

MXFP8 通常采用 **Per-Block** 细粒度量化，需要为每个数据块维护额外的缩放因子，并在计算过程中频繁访问这些元数据。相比之下，HiF8 由于动态范围较大，通常可以采用 **Per-Tensor** 量化，从而减少缩放因子的数量及其访存开销。对应收益主要包括：

* 缩放因子加载和存储次数减少；
* 显存中用于保存细粒度 Scale 的额外开销下降；
* 数据访问模式更连续，减少由碎片化元数据带来的对齐和访问问题。

### 6.2.2 控制逻辑相对简单

**Per-Block** 量化要求算子在执行过程中处理块边界切换、局部反量化以及跨块 Scale 对齐等逻辑，这会增加控制复杂度，并影响算子融合和流水化执行。相比之下，HiF8 采用**​ Per-Tensor** 路径时，算子内部数据流更为连续，相关控制逻辑也更简单，因此更容易获得稳定的执行效率。

### 6.2.3更适合 Delayed Scaling 训练

HiF8 具有更大的动态范围，因此在训练过程中可以采用更新频率较低的 Delayed Scaling，而不会明显影响训练稳定性。这使得其在以下方面具有一定优势：

* ​**Amax 统计频率较低**​；
* ​**Scale 更新及相关同步操作减少**​；
* ​**对主计算流程的干扰较小**​。

相比之下，动态范围较小的 FP8 / MXFP8 往往需要更频繁地更新缩放参数，或者依赖更细粒度的缩放策略，这会增加额外控制开销。

## 6.3 当前结论与后续优化空间

从当前实验结果看，HiF8 在大模型训练场景中表现出较好的应用潜力。

一方面，在现有实验配置下，HiF8 的损失曲线和梯度范数与 BF16 基本对齐，说明其在当前任务上能够保持较好的训练稳定性。另一方面，在端到端性能上，HiF8 同时优于 BF16 和 MXFP8，表明其在数值范围、量化粒度和系统开销之间取得了较好的平衡。

从实现角度看，HiF8 对细粒度缩放和大量元数据的依赖较低，这有助于降低算子实现复杂度，并为后续在更大规模训练任务中的扩展提供便利。

后续工作可以从以下几个方向继续展开：

* ​**扩大算子覆盖范围**​：将 HiF8 量化扩展到更多适合低比特化的算子，例如 **​FlashAttention（FA）​**及相关集合通信算子；
* ​**优化缩放更新机制**​：进一步研究更适合 HiF8 的 Amax 统计与 Scale 更新策略，以降低额外开销并提高数值稳定性；
* ​**开展软硬件协同优化**​：结合编译器和底层硬件指令能力，进一步优化低比特数据路径和算子融合实现。

# 第七章 推荐方案与实施指南

基于前述格式设计、量化方式和实验结果分析，本文总结了一组适用于大规模神经网络训练的推荐配置。

## 7.1 HiF8 训练推荐配置

在兼顾训练精度和系统吞吐的前提下，推荐配置如表 7 所示。

**表 7：HiF8 训练推荐配置**

| **配置维度** | **推荐方案** | **核心动机** |
| - | - | - |
| **量化粒度** | **Per-tensor** | 最大化 HiF8 格式优势，消除 Per-block 带来的访存与控制负担。 |
| **缩放策略**                                                                                      | **Delayed Scaling** | 减少 Per-Block 量化带来的元数据开销和控制复杂度 |
| **更新周期**                                                                                      | **Interval = 10 steps** | 利用 HiF8 的动态范围优势，降低缩放参数更新频率 |
| **覆盖算子**                                                                                      | **MM / GMM** | 优先覆盖计算密集型主干算子 |
| **Master Weights**                                                                                | **FP32 / BF16** | 保证参数更新阶段的数值精度 |

在模型和任务允许的情况下，建议优先采用 Per-Tensor 量化，以减少 Scale 元数据开销和实现复杂度。对于缩放策略，建议优先采用 Delayed Scaling，并将更新周期设置为 10 steps 或更高，以降低统计和同步开销。对于量化覆盖范围，可优先从 MM 和 GMM 等计算密集型算子开始，再逐步扩展到其他适合低比特化的算子。

## 7.2 核心方案优化建议

在实施上述方案时，建议遵循以下原则，以兼顾训练精度、系统效率与实现复杂度。

* **优先采用 Per-Tensor 量化。**
  由于 HiF8 具有较大的动态范围，在大多数 LLM 训练场景下，Per-Tensor 量化通常已能够满足精度需求。与细粒度量化相比，该方式可以显著减少 Scale 元数据的存储与访问开销，并降低访存碎片化和控制复杂度。
* ****优先采用 Delayed Scaling。****
  建议结合 HiF8 的数值范围优势，采用更新频率较低的 Delayed Scaling 策略，并将更新周期设置为 10 steps 或更高。这样可以减少 Amax 统计、Scale 更新及相关同步操作带来的额外开销，有利于提高主计算流程的连续性。
* **从数值能力、训练稳定性和系统开销三个方面综合评估方案。**
  HiF8 通过 Dot 域、无冗余阶码与 Denormal 扩展，在 8-bit 位宽下提供了较大的动态范围；在本文实验设置下，其损失曲线和梯度统计结果与 BF16 基本对齐，表现出较好的训练稳定性；同时，HiF8 支持较粗粒度量化和较长周期的缩放更新，有助于减少元数据访存与控制逻辑开销，并获得较好的端到端性能收益。

## 7.3 总结

本文围绕 HiF8 的数据格式设计、量化方案、训练框架支持以及实验结果进行了分析。实验表明，在 950DT 平台和裁剪版 DeepSeek-v3 模型上，HiF8 在保持与 BF16 相近训练精度的同时，相对 BF16 实现了 29.5% 的端到端训练加速，并相对 MXFP8 获得了 11.3% 的性能提升。

从当前结果看，HiF8 在数值范围、训练稳定性和系统开销之间取得了较好的平衡。​**对于希望降低访存压力、提升训练吞吐并控制实现复杂度的大模型训练场景，HiF8 是一种具有工程应用价值的 8-bit 混合精度训练方案**​。
